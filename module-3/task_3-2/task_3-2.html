  3. Discuss briefly how quickly or slowly a computer might be able to compute this, considering the number of guesses and the time it takes. How does the program behave while it is guessing? Can the program perform other tasks concurrently?

    4. A modern computer can compute this task incredibly fast because it is capable of executing millions of operations per second. Even when guessing a number between 1 and one million, the execution typically concludes within a few milliseconds. While the program is guessing, it runs synchronously. Because JavaScript is single-threaded, a heavy or continuous synchronous loop completely occupies the main execution thread. As a result, the webpage behaves as if it is temporarily "frozen" or unresponsive; user interface elements cannot be clicked, animations halt, and the screen does not update until the loop terminates. Due to this single-threaded architecture, the program cannot perform other tasks concurrently while the loop is running. It must finish finding the target number before the engine can move on to process any other events, inputs, or scripts.

  4. Explain the relationship between rows and columns in nested "for" loops. Can we, for instance, change the order, considering rows to be innermost or columns to be innermost, or does this not matter?

    5. In nested for loops, the relationship between rows and columns is determined by which loop is on the outside and which is on the inside. The outer loop functions as the primary "Row Maker," establishing the vertical grid structure. For every single iteration of the outer loop, the inner loop functions as the "Column Maker" and must complete its entire cycle to build the horizontal elements across that specific row. We can change the order by switching which loop is outermost or innermost, but doing so changes the logic and layout significantly. Because browsers and text strings read and render data sequentially from left to right, line by line, the outermost structure dictates how the final output is assembled. If we placed the columns on the outside and rows on the inside, the program would try to build the page vertically column-by-column, which would disrupt the intended layout unless we significantly changed how the text string is buffered and handled before printing. Therefore, the structural order matters deeply.
